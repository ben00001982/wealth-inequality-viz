# Beyond the Static Slide

An interactive narrative visualisation of United Kingdom wealth inequality, and its static
comparator, built as the artefact for an MSc Data Science thesis at UWE Bristol
(module UFCE9T-60-M).

The piece argues one thing across three dimensions: most wealth in Britain is housing, so whether
you own, when you were born and where you live decide who ends up wealthy. It is structured as a
martini glass (Segel and Heer, 2010): a guided, scroll-driven narrative that hands over to
reader-directed exploration.

## Status

The artefact builds and runs end to end in both A/B conditions. **The data it currently serves is
synthetic placeholder data**, generated by `scripts/make_synthetic.py`, with the right shape and the
wrong numbers. Every data file declares `__meta.synthetic: true`, and the application shows a
standing banner saying so. The banner disappears by itself once the real pipeline output replaces
those files.

The user study cannot run against a synthetic build. That is a launch precondition, not a
preference.

## Quick start

```bash
npm install
python scripts/make_synthetic.py    # placeholder data, so the app has something to render
npm run dev                         # http://localhost:5173
```

Add `?condition=static` or `?condition=interactive` to choose an A/B arm, and `&study=1` to reveal
the study harness bar with the telemetry export.

```bash
npm run build            # production build for GitHub Pages (base /wealth-inequality-viz/)
npm run build:local      # local-fallback build with a relative base, into dist-local/
npm run preview:local    # serve dist-local/ for an offline demo
python scripts/validate.py   # gate: structure, ranges, cross-file consistency, provenance
```

## The two conditions

The whole point of the study is that these two arms differ in exactly one thing.

| | Static | Interactive |
|---|---|---|
| Guided narrative, steps S0 to S17 | Scroll-only sticky charts | Same charts, staged emphasis within a chart |
| Per-step annotation | Present | Present, identical text |
| Missing-top caveat | Everywhere | Everywhere |
| S18 handover | Fixed typical renter against typical owner | Reader inputs, which seed the explorer |
| Explorer (E1.1 to E1.5) | Absent | Present |
| Timing view (E5) | Waves side by side | Interactive wave selection |
| Off the chart (E7) | Small multiple of the same frames | Interactive stepped zoom-out |

Both arms are rendered from one component tree, so content parity is a property of the code rather
than a promise in a document. What differs is gated through `can(condition, capability)`, reading a
single capability table in `src/state/conditions.js` transcribed from the frozen design spec. The
accessibility layer is deliberately not in that table: it is identical in both arms, because an
affordance present in one arm only would be a second manipulated variable.

## Stack, and why it is fixed

Vite, React (plain JavaScript), Vega-Lite via react-vega, Scrollama, Python and pandas for the data
pipeline, React-aria for accessible controls, localStorage telemetry, deployed to GitHub Pages as a
static site. The stack was fixed at proposal stage and is not open for substitution, D3 in particular.

Note for anyone following an older tutorial: this uses react-vega version 8, which exposes a single
`VegaEmbed` component rather than version 7's separate `<Vega>` and `<VegaLite>` components, with the
renderer and action-menu choices moved into an `options` object.

Two places where the stack constrains the design, both stated in the report rather than worked
around quietly:

**No tweened animation.** Vega-Lite has no first-class object-constant transition between arbitrary
specification states. One intended device, an animated reveal of the shift in wealth by age between
two survey waves, is therefore not available. The substitute is faceted small multiples, which is
not merely a fallback: static side-by-side traces are better for analytical comparison than
animation (Robertson et al., 2008; Tversky et al., 2002).

**No server.** Telemetry is localStorage-only with a participant-triggered export. That constrains
the study, because capture is not guaranteed and an abandoned session is lost. It also happens to be
the strongest data-protection position available: nothing is transmitted, so there is nothing in
transit to intercept and no store to breach.

## Data

Sources are the ONS Wealth and Assets Survey, the UK House Price Index, the English Housing Survey,
ONS housing affordability, and ONS Open Geography Portal boundaries, plus two published figures from
Advani, Bangham and Leslie (2021) and published aggregates from the Sunday Times Rich List.

Three things worth knowing before touching the pipeline.

**Nothing is invented.** Where a figure could not be confirmed against a primary source it is tagged
`confirm-at-build` in `src/data/narrative.js` and shows a build-time warning in development. One
claim carried by an earlier draft was withdrawn rather than replaced, because no published source
supported it.

**Geography is ITL1, formerly NUTS1.** The United Kingdom replaced NUTS with ITL from 2021. ITL1
mirrors the former NUTS1 at twelve areas, so the project's stated standard is superseded in name
only. Join on the code, never on the area name.

**The survey covers Great Britain.** Northern Ireland carries no wealth value on any map and must
render as a distinct no-data class, never as zero. The validator fails the build if it does not.

The three-way age-by-tenure-by-region cross-tabulation the explorer would ideally use is not
published by ONS. The pipeline ships the published marginals with nulls marking "all", and the
lookup degrades to the finest published cut and says which dimensions it had to drop. Synthesising
the interaction from the marginals would produce a number that looks like data and is not.

## Accessibility

WCAG 2.1 AA is the target and the audit checklist lives in `docs/ACCESSIBILITY.md`.

The hard part is that Vega-Lite renders to canvas or SVG, and neither is a chart an assistive
technology user can read. The answer here is a wrapper: SVG renderer, the chart presented as a
labelled image with a four-level description (Lundgard and Satyanarayan, 2022), and the underlying
numbers available as a real HTML table beneath every chart. The table is collapsed, not concealed,
because a sighted reader who cannot separate a colour scale needs it too.
